{% comment %} Poll container. It re-fetches `chores:board_list` every 10s (`hx-trigger="every 10s"`, the interval pinned by `_docs/design-system.md`) and swaps the result into its own contents (`hx-swap="innerHTML"`). It {% include %}s the exact same `_board_list.html` the endpoint returns, so the first paint and every polled refresh are byte-identical. Poll safety — `hx-sync="closest .board__poll:queue last"`: htmx inherits `hx-sync` down to the mark-done form / button in `_chore_row.html` (#11) and the swap form (#15, when present). `closest .board__poll` resolves to THIS container from the poll itself and from every inner form, so the poll and all in-list user actions share one request queue. `queue last` means a request that arrives while another is in flight is queued, never dropped and never aborted: a user-initiated mark-done / swap POST that starts mid-poll is queued and then runs; a poll that fires while a user POST is in flight is queued and runs after, by which point the POST has already swapped its own row, so the refresh has nothing to clobber. (`abort` was rejected: it has a race window where a user POST is dropped if a poll happens to be in flight when the user taps — the AC forbids that.) {% endcomment %}
