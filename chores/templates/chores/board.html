It re-fetches `chores:board_list` every 10s (`hx-trigger="every 10s"`, the interval pinned by `_docs/design-system.md`) and swaps the result into its own contents (`hx-swap="innerHTML"`, so every refresh replaces the whole daily / weekly list). It {% include %}s the exact same `_board_list.html` the endpoint returns, so the first paint and every polled refresh render from one template. Poll safety has two independent parts: 1. A user-initiated POST is never dropped — `hx-sync="closest .board__poll:queue all"`. htmx inherits `hx-sync` down to the mark-done button in `_chore_row.html` (#11) and the future swap form (#15). `closest .board__poll` resolves to THIS container from the poll itself and from every inner control, so the poll and all in-list user actions share one request queue. `queue all` keeps every queued request in arrival order and discards none: a user mark-done / swap POST that fires mid-poll is queued and then runs; a poll tick that fires mid-POST is queued and runs after. Nothing is ever aborted or discarded, so a user POST can never be the request that gets dropped. (`queue last` was wrong here: it keeps only the most recently queued request, so a user POST queued behind an in-flight poll could be discarded by a later tick. `abort` was wrong: it races a user tap against an in-flight poll.) 2.
